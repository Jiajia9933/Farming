# 技术架构

> 草案，需要产品/技术确认后再执行。

## 平台

微信小游戏（微信开发者工具 + 小游戏 API）。

## 客户端（Client/）

- 语言：TypeScript（见 [14_AI开发规范.md](14_AI开发规范.md)）
- 引擎：待定，目前是纯 Canvas + 手写场景切换（微信小游戏常见方案还有 Cocos Creator / LayaAir）
- 实际目录：`Client/src/{core,entities,scenes,ui,types}`，数值配置在 `Client/config/*.json`
- **美术/音频素材要放在 `Client/assets/` 下**（比如 `Client/assets/audio/`），不是仓库根目录的 `Assets/`——小游戏实际部署打包的是 `Client/` 这一层，`Assets/` 在包外面，运行时读不到。`Assets/` 目前只是早期文档占位，以后要么删掉要么明确改成"仅供设计稿存放，不进包"。

## 服务端（Server/）

- 是否需要服务端取决于是否要做好友互动、离线成长同步、防作弊：见 [13_游戏规则.md](13_游戏规则.md) 中"成熟时间以服务器时间计算"的规则，这意味着**需要服务端**。
- 语言：TypeScript（Node.js），与客户端共享类型定义
- 存储：待定（用户量小时可用轻量方案，如 SQLite/云数据库；预留迁移空间）

## 配置数据流

`Docs/` 中的数值表（经济系统、植物设计等）→ 转换为 `Server/configs/*.json` → 客户端和服务端共同读取，避免数值写死在代码里。
